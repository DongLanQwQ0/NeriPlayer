vivo 音乐适配
=============

已验证设备
V2527A / PD2527，OriginOS 6，Android 16 / API 36。
固件 PD2527_A_16.0.19.3.W10，原子随身听 com.vivo.musicwidgetmix 6.2.7.2。
其他固件的场景、模板及准入规则需要重新验证。

原生随身听
CarMediaBrowserService 同时声明 Android 标准浏览 action 与
com.vivo.musicwidgetmix.support.service，返回现有播放器的同一个 MediaSession。
保留原有调用方 UID / 系统媒体控制权限校验，不扩大浏览权限。
MediaSession.sessionActivity 提供返回应用的入口。

此设备需要系统音源名单配置。只向 musicwidget_list_pkg_type_key 添加包名，
会在随身听刷新支持名单时被移除。此次测试额外配置了 secure music_app_white_list，
并保留固件默认音源列表。该配置是经用户授权的本机 ADB 测试设置，生产应用不写此名单。

原生随身听面板可显示封面、歌名、歌手并执行播放、暂停和切歌。
顶部原生音乐岛另外检查随身听内部固定包名集合，音源名单配置不能解除该限制。
已补充原生列表浏览与红心协议；上述真机原生面板的列表点选及收藏状态回传已通过。
vivomusicmix_current_list、vivomusicmix_favorite_list、vivomusicmix_local_list
分别映射当前队列、应用收藏歌单和离线曲库。每页最多 50 首，读取
vivomusicmix_key_media_page，返回 vivomusicmix_key_has_more 与当前页号。
返回现有曲库的歌曲 ID，点选仍经过现有歌曲身份校验并复用同一播放器。
浏览列表不主动开始播放，也不启动播放前台通知。
原生红心通过 MediaSession 的 HEART rating 写入现有收藏操作；歌单变化时重新发布收藏元数据。
vivo 元数据 support_event 声明基础控制 1|2|4、跳转 16、允许收藏时的 64，
以及当前 / 收藏 / 本地列表 256|512|1024，避免已返回列表但原生入口仍被禁用；
需要应用内确认或歌单未就绪时不声明收藏能力。媒体时长优先使用播放器实际时长。
上述协议来自本机随身听版本的调用实现，其他版本仍需验证。循环模式及原生歌词协议尚未实现。

SuperX 自定义音乐岛
VivoMusicIslandBridge 使用独立场景 NERIPLAYER_MUSIC、独立通知频道和固定通知 ID。
它不替换播放前台通知，也不依赖原生随身听服务。
仅在 vivo 设备、通知和频道可用、且 getSceneStatus 明确返回 true 时发布。
关闭场景、没有曲目或释放播放会话时，按实际活动通知的 tag / ID 撤下。
展开卡片按原生音乐样式组织封面、歌名、歌词（无歌词时显示歌手）、进度、
应用入口与上一曲 / 播放暂停 / 下一曲 / 收藏。封面取色生成暗色渐变，位图按封面缓存。
以用户提供的网易云原生卡片为尺寸参考，在上述真机上校准边距和按钮位置。
上一曲、播放 / 暂停、下一曲使用圆角轮廓。爱心按网易云参考图缩小，状态图四周内缩 5dp，保留 44dp 点击区域及原有中心位置。
控制行向标题内容留白扩展时，中间容器不裁切，外层系统卡片保留边界。
收起态采用封面与系统音律动画；rightTemplate=1，waveState 同步播放状态，
waveColor 提供青蓝两色。已在真机连续帧中观察到音律条高度变化。
歌词使用现有外部歌词数据流，进度使用现有播放状态回调；熄屏不因进度重发卡片。
收藏复用现有业务操作，需要交互确认时进入应用；点击正文和应用图标返回应用。
进度条支持点按位置跳转，分为四十等分（含起终点共四十一个热区），复用同一播放器的 seek。
请求携带歌曲身份，旧卡片不能跳转新歌；未知时长不提供跳转。
时长优先采用当前播放器的实际媒体时长；试听流按试听长度显示和跳转，避免把歌曲标称时长当作可播放范围。
标准 RemoteViews 不支持 SeekBar 或拖动回调，因此不提供连续拖动。
点按热区无独立水波纹，避免窄热区出现竖向闪带。当前进度直接设值；点按跳转和正常播放的连续横向动画尚未实现，RemoteViews.setProgressBar 不提供 animate 参数。
播放和收藏采用系统 CheckBox 状态图，触摸后立即切换图标，再通过显式 PendingIntent 下发目标状态。
进度跳转立即预览目标位置。待确认状态最多保留三秒，确认后使用真实状态，超时回滚，切歌或撤下时清理。
自定义卡片要求 Android 12 / API 31 及以上，以使用 RemoteViews 的勾选状态回调。
通知卡片与展开卡片分别构建，展开卡片额外预留状态栏摄像头安全空间。
模板 7 和显示掩码 0x111 是上述固件的实测配置。
自定义路线自行绘制歌词和播放进度，未接入 vivo 原生音乐歌词专项协议。
进度热区的 PendingIntent 与描述按歌曲身份和实际时长缓存，普通进度刷新复用缓存。
使用 addStableView 保留热区稳定 ID；每张卡片克隆子 RemoteViews，避免共享可变布局根。
切歌或实际时长改变时重建缓存，撤下时清理。尚无真机帧耗时数据，流畅度改善待实测。

通知去重进展
当前仍分别发布前台媒体通知与 SuperX 卡片，原生随身听还会提供系统控制面板。
单独把显示掩码改为 0x100 的真机试验仍能在通知栏看到 SuperX 卡片，生产配置保留 0x111。
通知合并尚未实现；后续必须同时验证前台服务存活、系统 tag 转换、更新与撤下，保留后台播放能力。
同一真机的隔离前台服务试验发现：先发布标准 MediaStyle 前台通知，再用相同 ID 发布
SuperX 卡片，系统仍保留两个身份：无 tag 的通知 flags=8290，VIVO_SUPERX_TAG 的
通知 flags=8234。等待五秒仍未合并；仅前者带 FLAG_FOREGROUND_SERVICE（64）。
因此“改成同一个 ID”不能完成通知去重，也不能通过取消前者来保留可靠的后台播放。
VivoMergedForegroundTest 使用独立测试 ID、独立会话与静音 AudioTrack，不控制用户播放器。
2026-10-23，通过 USB 在上述真机完成两条路径的创建、后台保持十秒、更新、停止与撤下检查：
foreground-update 先启动标准通知，再通过 startForeground 更新为 SuperX，仍有上述两个身份。
foreground-direct 首次就用 SuperX 启动，只保留 VIVO_SUPERX_TAG、flags=8234 的一个身份。
虽然直接路径的通知没有 FLAG_FOREGROUND_SERVICE，ActivityManager 与系统服务记录均为
isForeground=true、foregroundId=1313927239、mediaPlayback 类型；后台更新后仍只有一条。
因此不能单凭通知 flags 判定服务失去前台状态。生产通知合并尚未接入。
现有生产服务首先发送标准 bootstrap；只改后续更新调用仍会产生重复通知。
继续接入时应从首次前台通知处理，并验证场景关闭、暂停与重新启动的真实播放器生命周期。
空音频探针退到后台时曾被此固件冻结；上述通过结果使用独立静音音频流，未请求音频焦点，
测试结束释放音频、会话和所有独立测试通知，不依赖调整手机电池策略。
该固件 RemoteViews.DrawInstructions 的版本为 6，能膨胀 RemoteComposePlayer；
VivoRemoteDrawingDeviceTest 已通过基础渲染器检查。

Chrona 的日程卡，音乐岛展开区域的缩放与连续动画仍待检查，未关闭其他应用的卡片。

700ms 的离屏绘制进度宽度由 19px 变为 78px，连续时间表达式渲染检查通过。

这些试验证明系统宿主连续绘制与点击的基础路线可行，完整音乐卡片尚未接入生产。

测试场景配置
应用不会注册或强开系统场景。instrumentation 单包配置入口仅适用于该场景只配置一个
测试包的情况；需要应用包和测试包使用相同签名，系统安装确认由用户操作。

该固件 setSuperXInfosSceneList 的四个列表按场景行对应；每行第三、第四项内部
分别用连字符连接多个包名与开关。同名场景行会覆盖旧行，不能为每个包各写一行，
也不能在多包共存时直接运行旧单包配置或 Restore-VivoMusic.ps1。

当前手机 NERIPLAYER_MUSIC 的配置为一行：
sceneList=[NERIPLAYER_MUSIC]
switchList=[true]
pkgNameList=[moe.ouom.neriplayer.debug-moe.ouom.neriplayer.vivo]
pkgSwitchList=[true-true]

登记前后场景表比较仅增加正式包；其他原有配置保留。正式包已实际发布
VIVO_SUPERX_TAG / ID1313887817 / neriplayer_vivo_music_island，手机顶部出现封面与音律动画。
无需重装或重构建应用，播放状态未改。当前设备 ADB shell 的 INotificationManager 查询
签名为 getSceneStatus(String packageName, String scene, int userId)，当前用户为 0。
