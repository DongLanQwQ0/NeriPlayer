vivo 独立正式版性能验收（2026-10-23）
=================================

设备：vivo V2527A / PD2527，OriginOS 6，Android 16 / API 36。
本地候选：538b6eba.10231927-vivo，versionCode 214918026；包含随后提交的 Cookie 锁顺序修复。
包名 moe.ouom.neriplayer.vivo，arm64-v8a，非 debuggable，R8 与资源缩减启用。
独立固定 release 签名；与原版、debug 版及其数据并存。

启动阻塞及修复
初始候选在完成首次引导后，三次冷启动均超时。应用自身线程采样并使用对应 R8 mapping
还原后确认：主线程在 HomeViewModel 构造时持有 neteaseClient 的 lazy 锁，等待 Cookie
仓库锁；后台 Cookie 观察器持有仓库锁，等待相同 lazy 锁，形成死锁。
现在在注册观察器时先取得仓库和客户端引用，再收集 Cookie；持有仓库锁的回调只操作
已经初始化的客户端。withCurrentCookiesIfMatches 仍阻止过期账号快照恢复旧会话。
加密仓库构造、账号观察器及 YouTube 启动预热放在既有 IO scope，代理引导仍同步完成。
临时线程采样代码已移除，正式版不附带此次诊断探针。

解释与复现条件
两包没有统一账号数据或主题：旧 debug 为现有真实数据与玻璃样式，新独立正式版为
单独配置与上游新版默认样式。冷启动基线采于同日下午，正式版通过无线 ADB 测试，
耗时取设备内部 TotalTime。上述结果用于实际版本验收，不是仅隔离编译类型变量的 A/B。
同一包三次冷启动也会受到系统文件缓存、JIT 和网络加载状态影响。
原始启动输出、gfxinfo、压缩截图和还原堆栈位于本机 F:\Android\NeriPlayerChecks。
