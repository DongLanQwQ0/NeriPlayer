自动跟随上游 Release
===================

目标仓库：DongLanQwQ0/NeriPlayer
上游仓库：cwuom/NeriPlayer
入口：.github/workflows/vivo_upstream.yml

发布流程
每半小时检查上游新 Release，也可手动运行。以 Release 标签解析出的精确提交为输入，
合并到派生仓库 master 并推送；随后检出合并提交，测试、构建、签名并发布。
从上游 Release 421509148（NeriPlayer-224df247.10231345）开始跟随，不补发旧版 debug 包。
不再逐个构建上游 commit；预发布仍标为 prerelease。每轮处理一个 Release，串行合并，
积压在后续轮次继续处理。GitHub 定时任务可能延迟，不承诺发布后立即完成。

保留明确的 merge 历史和 fork 适配，不使用补丁重放、强推或静默解决源码冲突。
合并冲突时不推送；测试、构建或签名失败时不发布，修复后重试同一上游 Release。
构建固定使用本轮合并 SHA，不会在构建过程中切换到后来更新的 master。
完成标记为非草稿 Release，以及非空 APK、对应源码 ZIP 两个附件。
失败草稿在重试时补齐附件后发布；已经发布的版本不会因定时检查而反复覆盖。

优化版 APK
使用 :app:assembleVivoRelease，包名 moe.ouom.neriplayer.vivo，显示名称 NeriPlayer vivo。
该 variant 继承 release 的 R8 优化、代码及资源缩减，不可调试，模块使用 release 依赖。
默认仅构建 arm64-v8a；debug 和上游原版构建入口不变。
独立包与原版、现有 .debug 并存，首次安装需导入数据并重新配置目标设备的 vivo 场景权限。
不自动修改系统准入名单。正常播放器、队列、收藏和通知语义继续使用现有实现。
versionCode 使用自 2020-01-01 UTC 起的秒数；CI 将同一构建的值显式传入 Gradle，
版本名称包含上游标签与合并提交。没有把可调试 APK 改名成 release。

签名与源码
独立、长期固定的 PKCS12 release 证书，不复用 debug 测试证书或上游作者证书。
私钥和口令不提交到仓库。先验证 keystore 格式、别名，再确认包名且拒绝 debuggable APK，
签名后执行 apksigner verify --print-certs。更换证书会影响已安装版本的覆盖升级。
签名使用单独 runner；该 runner 不检出、编译或执行上游源码。
构建 runner 不接触私钥；R8 mapping 和测试报告保存在 Actions 附件中。
Release 附带实际合并源码 ZIP（含子模块），保留 GPL 与第三方许可证。
GitHub 自动生成的 Source code 附件以 release 指向的合并提交为基础。

仓库配置
Actions Secrets：
  VIVO_RELEASE_KEYSTORE_B64：固定 PKCS12 私钥库的 Base64。
  VIVO_RELEASE_STORE_PASSWORD：私钥库口令。
  VIVO_RELEASE_KEY_PASSWORD：密钥口令。
  VIVO_RELEASE_KEY_ALIAS：neriplayer-vivo-release。
使用受支持的凭证工具配置 Secrets，禁止写入源码或日志。
私钥库与可独立恢复的口令应分别离线备份；GitHub Secrets 不能作为可下载的密钥备份。
本机 password.dpapi 绑定 Windows 用户，单独复制它不等于跨电脑恢复口令。

邮件通知
用户已配置 GitHub Release 通知。完成签名与附件上传后，最后将 Release 从草稿发布，
由 GitHub 按账号订阅和邮件设置投递通知；不在 CI 保存邮箱密码。
失败不发布 Release，可通过 Actions 失败通知获知，不能把未完成构建写成发布成功。
